# Сервер авторизации

Курсовой проект на языке C99. Вариант № 15, базовый уровень.

## Назначение программы

Консольная программа обрабатывает сообщения сервера авторизации.
Она проверяет введённые данные, отбрасывает повторные записи,
сохраняет события в текстовый архив и выводит статистику.

## Индивидуальное задание

Вариант № 15 — «Сервер авторизации».
Уровень сложности — базовый.

Требуется реализовать обработку сообщений следующего формата:

`час:минута node logins failures`

Структура Event содержит пять полей:
h, m, node, logins и failures.

Основные требования:

- Архивировать записи при заполнении буфера на 80 процентов.
- Считать запись дубликатом при совпадении узла node
  и основного показателя.
- Выводить количество полученных записей, отброшенных дубликатов
  и записей, сохранённых в архив.
- Дополнительный поиск и сортировка не требуются.

## Особенности реализации

- Буфер рассчитан на 10 записей.
- Автоматическая архивация выполняется после накопления 8 записей.
- Основным показателем для сравнения принят failures —
  количество неудачных попыток входа.
- Дубликаты проверяются среди записей текущего буфера.
- Архив сохраняется в файл archive.txt.
- Новые записи дописываются в конец существующего архива.
- Перед завершением программы остаток буфера сохраняется в архив.
- Для завершения ввода необходимо нажать Enter на пустой строке.
- Полученными считаются корректные записи, включая дубликаты.
- Итоговые счётчики относятся к текущему запуску программы.
## Основные функции программы

### main

**Принимает:** параметров нет. Сообщения вводятся с клавиатуры.

**Возвращает:** 0 при успешном завершении или 1 при ошибке
чтения входных данных либо записи в архив.

**Что делает:** организует ввод сообщений, проверяет формат
и допустимость значений, вызывает проверку дубликатов.
Сохраняет принятые записи в буфер и запускает архивацию
при заполнении на 80 процентов. Перед завершением сохраняет
остаток буфера и выводит итоговую статистику.

### is_duplicate

**Принимает:**
- ptrbuffer — массив записей текущего буфера;
- count — количество записей в буфере;
- current — новую запись для проверки.

**Возвращает:** 1, если дубликат найден, или 0, если его нет.

**Что делает:** последовательно просматривает записи буфера
и сравнивает поля node и failures с новой записью.
Совпадение обоих полей означает наличие дубликата.

### archive_events

**Принимает:**
- ptrbuffer — массив записей для сохранения;
- count — количество сохраняемых записей.

**Возвращает:** количество записанных событий при успешном
сохранении или -1 при ошибке открытия, записи либо закрытия файла.

**Что делает:** открывает файл archive.txt в режиме дописывания,
записывает каждое событие отдельной строкой и закрывает файл.
Если файл отсутствует, создаёт его.
## Сборка и запуск

Программа предназначена для запуска в Windows.
Исходный файл main.c сохраняется в кодировке UTF-8.

Для сборки компилятором Microsoft C необходимо открыть
Developer PowerShell для Visual Studio и перейти в папку проекта.

Команда сборки:

```powershell
cl /nologo /utf-8 /W4 main.c /Fe:main.exe
```

Команда запуска:

```powershell
.\main.exe
```

При настроенном компиляторе программу также можно собирать
и запускать через VS Code.

## Команды программы

| Команда | Назначение |
|---|---|
| `/help` | Показывает формат сообщения, пример и правила ввода |
| `/stats` | Показывает текущую статистику и заполнение буфера |
| `/buffer` | Показывает записи текущего буфера |

Команда помощи доступна во время ввода сообщений.
После вывода подсказки программа продолжает принимать записи.
Команда не увеличивает счётчики событий и не сохраняется в архив.

### Просмотр текущей статистики

Команда /stats выводит количество полученных корректных записей,
отброшенных дубликатов, архивированных событий и записей в буфере.

После выполнения команды ввод сообщений продолжается.
Команда не изменяет счётчики и содержимое буфера.

Например, в новом запуске введём:

```text
09:30 node1 12 2
10:00 node1 20 2
/stats
```

Результат:

```text
Текущая статистика:
Получено записей: 2
Отброшено дубликатов: 1
Записано в архив: 0
Записей в буфере: 1 из 10
```

Одна запись принята, вторая отброшена как дубликат.
Принятая запись ожидает сохранения в архив.

### Просмотр буфера

Команда /buffer выводит записи, находящиеся в текущем буфере.
Для каждого события показываются время, имя узла,
количество входов и количество неудачных попыток.

Например, в новом запуске введём:

```text
09:30 node1 12 2
10:15 node2 8 1
/buffer
```

Результат:

```text
Текущий буфер:
09:30 node1 12 2
10:15 node2 8 1
```

Если буфер пуст, выводится сообщение «Буфер пуст.».

Просмотр сохраняет содержимое буфера и значения счётчиков.
После выполнения команды ввод сообщений продолжается.
После успешной автоматической архивации буфер становится пустым.

## Демонстрация работы

Последовательно введём три сообщения:

```text
09:30 node1 12 2
10:00 node1 20 2
10:05 node1 20 3
```

После третьего сообщения завершим ввод пустой строкой.

Первая запись будет принята.
Вторая будет отброшена как дубликат: совпадают node и failures.
Третья будет принята, поскольку значение failures отличается.

Фрагмент итогового вывода:

```text
Оставшиеся записи сохранены в архив.
Получено записей: 3
Отброшено дубликатов: 1
Записано в архив: 2
```

В конец файла archive.txt будут добавлены строки:

```text
09:30 node1 12 2
10:05 node1 20 3
```

При накоплении восьми записей архивация выполняется автоматически,
после чего буфер снова заполняется с начала.

## Заключение

В проекте реализованы ввод и проверка сообщений сервера авторизации,
отбрасывание дубликатов в текущем буфере и сохранение записей в архив.

Для хранения событий использована структура Event и массив записей.
Итоговая статистика показывает количество полученных корректных
записей, отброшенных дубликатов и архивированных событий.
